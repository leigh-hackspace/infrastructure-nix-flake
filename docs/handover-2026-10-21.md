# Handover — 2026-10-21, after the router cutover

The gateway (`machines/gw/`) is the network's router at **10.3.1.1** as of this evening;
the OPNsense appliance is retired. This is the state it was left in, what was fixed,
and what still has to be done. Read `machines/gw/README.md` before touching the router
and `docs/gw-cutover-attempt-2026-10-21.md` for the post-mortem.

## What was broken, and what was done

1. **`*.int.leighhack.org` was NXDOMAIN.** gw is authoritative for the zone and serves
   vhost names from `/var/lib/dnsmasq/names.hosts`, which a fresh box creates **empty**.
   dns-sync could not fill it (it is OPNsense-shaped and its pinned host key is the old
   box's). Restored by hand from the old box's archive
   (`~/tmp/opnsense-archive-20261017/dnsmasq-hosts` on services1, 183 lines) and
   `kill -HUP` to dnsmasq. **This is imperative state, not in git, and nothing
   refreshes it.**
2. **No inbound NAT at all.** Every `81.187.195.17`/`.18` service timed out from the
   internet and from the LAN (no reflection). Added `machines/gw/firewall.nix`'s
   `dstnat` chain (the old box's `rdr` table), `ct status dnat accept` in forward, a
   hairpin `masquerade`, and `DMZ_NET` in `markLocalV4` (the mark runs at `mangle`,
   before `dstnat`; without it hairpinned packets went out the uplink).
3. **dnsmasq stopped sending unsolicited RAs** after `router-lan` lost carrier at
   17:14:30 (the cutover cabling). Clients lose their IPv6 default when the 1200 s
   router lifetime expires — 20 minutes later — and dual-stack names hang on IPv6
   before falling back. `systemctl restart dnsmasq` restored the timer; verified with
   `journalctl -u dnsmasq | grep RTR-ADVERT(vlan225)` and services1's
   `ip -6 route show default` refreshing.

Verified from services1 (a LAN client, so the public addresses exercise the hairpin):

```
filestore.int.leighhack.org   IPv4 200   IPv6 200
id.leighhack.org              IPv4 302   IPv6 302
tailscale.leighhack.org       IPv4 301
yunohost.leighhack.org        IPv4 302   (-k; see below)
```

`just check` now passes **on gw** with zero `rustc`; `just fmt`/`fmt-check` no longer use
the devShell (see "Do not build on the router" in `docs/nix-dev-workflow.md`).

## Do next, in order

### 1. Port dns-sync to gw (blocking new DNS records)

Until this is done, the `*.int` names are the hand-restored file above, and a new/renamed
vhost gets no DNS. Everything below is for someone with the repo on a build box
(services1 or aibox — **not gw**).

- [ ] **Repin the router host key.** `just router-known-hosts` prints gw's key line
      (`GW_HOST` now defaults to `10.3.1.1`). Put it in
      `machines/services1/dns-sync.nix`'s `environment.etc."dns-sync/known_hosts".text`
      in place of the three OPNsense lines. network-status reads the same file.
- [ ] **`crates/dns-sync/src/main.rs`:**
      - `DEFAULT_ROUTER` → `leigh-admin@10.3.1.1` (root is not keyed on gw; prefix the
        command with `sudo -n`). Remove the python3 scripts — gw has no python3.
      - `check`: read `/var/lib/dnsmasq/names.hosts` (`sudo -n cat`), not
        `/var/etc/dnsmasq-hosts`.
      - `sync`: for each name in `/etc/dns-sync/expected-int-names` (all point at
        services1, 10.3.1.20) that is missing, **add a line** to `names.hosts`; preserve
        every other line (the file also carries cameras, APs, Pi Room boards and
        `authentik.int`, which the flake does not own). Write atomically, `root:root
        0644`, then `sudo -n systemctl reload dnsmasq` (SIGHUP is enough — dnsmasq
        re-reads `addn-hosts`, and the file is not a store path so it cannot be a
        `restartTriggers` value).
      - `prune`: remove only names that were in `/var/lib/dns-sync/last-expected` and are
        no longer expected — never the non-managed lines.
      - Keep `sync` strictly additive, as today.
- [ ] **Deploy services1** (`just switch` on services1, with the GOLDEN RULE confirm in
      the same invocation). The build goes to aibox.
- [ ] Verify: `just dns-sync-check` (0 missing), then `dig @10.3.1.1 <new-name>`, then
      `just dns-sync-sync` and `just dns-sync-prune`.
- [ ] Do not run `prune` before `sync` has written `last-expected`; the hand-restored
      file is the baseline.

### 2. Renew the yunohost certificate (out-of-band)

`yunohost.leighhack.org` is going to the right place (`81.187.195.18` → `10.3.1.15`,
ports 80/443 open) but its Let's Encrypt cert **expired 2026-10-21 16:59:23 UTC**.
Renewal is on the appliance (`yunohost domain cert renew`, or the admin UI); the
machine-hop key is not authorized on 10.3.1.15, so this needs someone with its
credentials. Inbound `:80` reaches it again now, so the HTTP-01 challenge will work.
Verify with
`openssl s_client -connect 81.187.195.18:443 -servername yunohost.leighhack.org`.

### 3. Make the RA/link-flap failure impossible to miss

A `router-lan` link flap stops dnsmasq's unsolicited RA timer until dnsmasq restarts;
WiFi clients then lose IPv6 20 minutes later. Either:

- add a hook that restarts dnsmasq when `router-lan` regains carrier (networkd
  dispatcher / a small systemd unit), **or**
- move router advertisements to `radvd`, which re-advertises on link-up.

At minimum add a check (gatus or a timer) that the RTR-ADVERT cadence and a host's IPv6
default are fresh, and put "restart dnsmasq after cabling" in the cutover runbook.
`machines/gw/README.md`, "The third way dnsmasq breaks the LAN silently".

### 4. Port network-status to gw

`crates/network-status/` still ssh's to `root@10.3.1.1` and runs OPNsense commands
(`main.rs` says so in its header and at `root@10.3.1.1`). gw has no root login, no
`pluginctl`, no `/conf/config.xml`. It needs the same treatment as dns-sync
(`leigh-admin` + `sudo`, NixOS readers) or it will show a dead router.
`network-info.int.leighhack.org` and its gatus checks are affected.

- **`authentik.int.leighhack.org`** resolves to `10.3.1.36`, whose `:443` is closed; the

- **OpenVPN** was off before the cutover and is still off
  (`machines/gw/openvpn.nix`, `enable = false`). Nothing inbound on 1194 is forwarded;

- **DHCPv6-PD** was never observed; IPv6 transit works because AAISP routes the `/48`
  and gw has static per-VLAN `/64`s. Confirm the delegated prefix (`networkctl status
  ppp0`, `ip -6 route`) before relying on it moving.

## Invariants that caused trouble today

- **Never build on gw.** `nix develop` compiles the pinned `wasm-bindgen-cli` with
  cargo, and gw has no remote builder. `just check`/`just fmt` are safe; the build-shaped
  recipes refuse via `_build-host-guard` (`INFRA_ALLOW_BUILD_ON_ROUTER=1` overrides).
- **Restart dnsmasq after cabling on the router.** It is not automatic, and the damage
  appears 20 minutes later.
- **`/var/lib/dnsmasq/names.hosts` is mutable and now load-bearing.** tmpfiles only
  creates it when missing; nothing in the flake rewrites it. Do not delete it before
  dns-sync can recreate it.
- **Confirm every switch/boot in the same shell invocation** (`just switch` does this).
  All machines still run `system.autoRollback`.
