The network's edge firewall / router / DNS server / DHCP server. Managed
out-of-band from this repo — there is **no flake configuration for it**.

## DNS (dnsmasq — this is what we sync with nginx)

The router runs **dnsmasq** (not unbound) for both DNS and DHCP. It is the
resolver that every LAN client and NixOS box uses (`DNS = 10.3.1.1`).

- `/usr/local/etc/dnsmasq.conf` — auto-generated by OPNsense. **Do not edit**;
  the header says so and a GUI/config change rewrites it.
- `/conf/config.xml` — the OPNsense source of truth. Host overrides live under
  `<opnsense><dnsmasq><hosts>`; aliases are a comma-separated `<aliases>` list.
- `/var/etc/dnsmasq-hosts` — dnsmasq's `addn-hosts` dump of host overrides +
  static DHCP reservations. **This is the file that actually answers
  `*.int.leighhack.org` lookups.**
- `conf-dir=/usr/local/etc/dnsmasq.conf.d,*.conf` — the supported spot for any
  hand-written dnsmasq additions (survives GUI rewrites, but is not managed by
  this repo).

### Adding / changing a name

Edit the host override in the OPNsense web UI (Services → Dnsmasq DNS →
Host overrides), or directly in `/conf/config.xml` (then restart dnsmasq).
OPNsense flushes `/var/etc/dnsmasq-hosts` from the config; verify with:

```sh
ssh root@10.3.1.1 'grep <name> /var/etc/dnsmasq-hosts'
```

A single host override `<host>services1</host>` maps **25 names** to all three
of services1's addresses (`10.3.1.20`, `2001:8b0:1d14:225::20`,
`fd99:dead:beef:225d::20`):

```
services1, mqtt, nginx, ldap, id, ha, firewall, truenas, unifi-admin,
grafana, filestore, monster, uptime-kuma, frigate, access-api, retro,
tailscale, zigbee2mqtt, login, gitlab, gatus, ai, mcp, status,
aibox.status
```

(all `.int.leighhack.org`; verified live 2026-08-26)

Notes:

- Several names point at the services1 **reverse proxy** rather than the
  backend directly: `truenas.*` → NAS at 10.3.1.6, `firewall.*` → router's
  60443, `monster.*` → 10.3.1.11:8006, `unifi-admin.*` → UniFi controller.
- `aibox.int.leighhack.org` → 10.3.1.32 (its own record — not services1).
- Inconsistency: services1 `networking.nix` `extraHosts` maps
  `unifi.int.leighhack.org` → 10.3.1.21, but the router has **no**
  `unifi.int.leighhack.org` record (only `unifi-admin.int`).

## DHCP

Static leases are also `dhcp-host=` lines in the same dnsmasq config. Key
reservations: `services1` (10.3.1.20, MACs `c8:d3:ff:a5:b2:25`/`c8:d3:ff:a5:be:7c`),
`aibox` (10.3.1.32), `nas2`/`nas1` (TrueNAS 10.3.1.6/10.3.1.5), `apps1`
(10.3.1.30), `yunohost` (10.3.1.15).

## Syncing DNS ↔ nginx vhosts (workflow)

1. Add the nginx `virtualHost` in `machines/services1/services/*.nix` (public
   apps via `mkSSOVirtualHost`; internal apps are `*.int.leighhack.org` vhosts
   with `CONFIG.LOCAL_NETWORK` ACLs).
2. Add the name to the router: extend the `services1` host override's
   `<aliases>` (or add a new host record) so dnsmasq answers it.
3. Verify from the router: `grep <name> /var/etc/dnsmasq-hosts`, and live:
   `getent ahostsv4 <name>.int.leighhack.org` (must be `10.3.1.20`).
4. The wildcard ACME cert (`*.int.leighhack.org`) already covers new names — no
   cert work needed. Public `*.leighhack.org` names need the public DNS record
   (points at the box's public IP) — not handled on the router.
